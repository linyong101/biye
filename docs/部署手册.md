# Vigil 部署手册

> 面向「把系统交付给企业 / 在服务器上长期运行」场景。开发调试请用 README 的 `npm run dev` 方式，本文档是容器化部署。

---

## 一、环境要求

- Docker Engine ≥ 20.10 或 Docker Desktop（Windows / macOS 需先启动 Docker Desktop）
- 内存 ≥ 1 GB（PostgreSQL + Redis + 两个 Node 服务）
- 端口：8080（看板）、3001（采集服务）、5432 / 6379（数据库与缓存，默认仅在容器内暴露，可不外放）

---

## 二、一键部署

```bash
# 1. 进入项目根目录
cd vigil

# 2. 启动全部服务（后台运行）
docker compose up -d

# 3. 查看状态
docker compose ps

# 4. 查看采集服务日志（首次启动会自动创建 admin 账号并执行 db push）
docker compose logs -f server
```

启动完成后：

| 地址 | 说明 |
| --- | --- |
| http://localhost:8080 | 分析看板（默认账号 admin / admin123） |
| http://localhost:3001/api/health | 采集服务健康检查 |

> ⚠️ 首次部署请立即登录看板，到「设置 → 账号 → 修改密码」改掉默认密码。

## 三、关键环境变量

在 `docker-compose.yml` 的 `server` 服务 `environment` 中配置：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DATABASE_URL` | 容器内 Postgres 地址 | 生产可换为独立数据库 |
| `PORT` | 3001 | 服务端口 |
| `DASHBOARD_ORIGIN` | http://localhost:8080 | CORS 白名单 |
| `JWT_SECRET` | （compose 中未设，请用随机串覆盖） | **生产必须修改**，否则 token 可被伪造 |
| `AI_API_KEY` | 空 | 填了则启用真实大模型诊断，否则走规则库兜底 |
| `AI_BASE_URL` / `AI_MODEL` | DeepSeek | 兼容 OpenAI 规范的大模型地址 |

`JWT_SECRET` 生成示例：

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

在 `docker-compose.yml` 的 server 段补一行：`JWT_SECRET: "<上一步输出的串>"`。

## 四、切换生产数据库（PostgreSQL）

容器编排里已内置 PostgreSQL，无需额外操作。若要用外部数据库：

1. 修改 `apps/server/prisma/schema.prisma`：`datasource db { provider = "postgresql" }`
2. 重新生成并同步：`npx prisma generate && npx prisma db push`
3. 把 `DATABASE_URL` 指向外部库

> SQLite 仅适用于单机演示；多副本部署必须改用 PostgreSQL（无文件锁，支持并发写入）。

## 五、SDK 接入（采集端）

在你的前端项目里：

```bash
npm i @vigil/web-sdk
```

```ts
import { init } from '@vigil/web-sdk'

init({
  appId: 'your-app-id',
  endpoint: 'https://your-domain.com/api/report', // 改为你的采集服务域名
  debug: false,
})
```

> `appId` 会作为 Project 自动创建，无需在服务端预先登记。

## 六、Source Map 上传（让堆栈可还原）

在 CI 构建后把 map 上传到采集服务（需管理员 token）：

```bash
curl -X POST https://your-domain.com/api/sourcemap \
  -H "Authorization: Bearer <ADMIN_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "appId": "your-app-id",
    "release": "1.0.0",
    "fileName": "assets/index.js",
    "content": "'"$(cat dist/assets/index.js.map)"'"
  }'
```

本地可用项目自带的端到端脚本验证整条链路：

```bash
npm run sourcemap:demo
```

## 七、验证清单

部署后逐项确认：

- [ ] `docker compose ps` 四个服务均为 `healthy / running`
- [ ] 浏览器打开 `:8080` 能进入登录页
- [ ] 用 admin / admin123 登录成功
- [ ] `:3001/api/health` 返回 `{ "ok": true }`
- [ ] 在页面触发一个错误后，看板能在数秒内出现对应问题
- [ ] 「问题详情」页能看到还原后的源码位置（需先上传 Source Map）

## 八、停止与清理

```bash
docker compose down          # 停止但保留数据卷
docker compose down -v       # 停止并删除数据库数据卷（慎用）
```
