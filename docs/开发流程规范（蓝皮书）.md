# 开发流程规范（蓝皮书）

> 适用对象：高职软件技术专业 · 毕业设计《Vigil 前端监控与诊断平台》
> 第一原则：**降低出错率**。所有开发必须按计划、有文档、有测试地进行。

## 0. 总则

- **技术栈（固定）**：后端 `Node.js`（Fastify + TypeScript + Prisma + SQLite），前端 `React + TypeScript`。
  - 不引入 PHP / Python 对后端做重写——对已成型项目推倒重来是最大出错源，违背"降出错率"初衷。Node.js 本身即在建议语言范围内。
- **不实现任何支付 / 交易相关功能**（订单、金额、支付网关一律不做）。
- **新增功能闸门**：任何新增功能或接口，**必须先写《需求说明》+《接口草案》交指导老师确认，确认后方可开发**。未确认的一律不动代码。

---

## 阶段 0 · 需求确认闸门

1. 提交《功能需求说明》：做什么、为什么、预期效果、工作量估计。
2. 附《接口草案》：URL、方法、请求体 / 响应示例、错误码。
3. 指导老师确认后进入开发；需求变更同样需再次确认。

## 阶段 1 · 数据库先行

1. 在 `apps/server/prisma/schema.prisma` 定义模型、字段、关系、索引。
2. 产出表结构 / ER 说明，与老师确认数据模型。
3. 同步结构：`npm run db:push`（开发环境）。
4. 演示数据用 `npm run seed` 预置，不把假数据硬编码进业务逻辑。

## 阶段 2 · 后台 API（先于前端）

1. **先写接口文档**：在 `docs/API文档.md` 登记每个接口的 URL / 方法 / 请求体 / 响应 / 错误码。
2. 实现接口逻辑。
3. **同时写接口测试**：在 `apps/server/test/<module>.test.ts` 用 `app.inject()` 覆盖该模块**每个接口**（正常路径 + 鉴权 + 参数校验 + 错误码）。
4. **规则：本模块测试未通过，不得视为完成、不得合并。**
5. 本地验证：`cd apps/server && npm test`。

## 阶段 3 · 前端

1. 前端只消费已文档化、已测试的 API；不在前端写绕过后端的数据逻辑。
2. 本地联调使用真实后端（`npm run dev`）。

## 阶段 4 · 质量门禁

- 每个接口都有对应测试文件。
- `docs/API文档.md` 与代码保持同步（改接口必须改文档）。
- 提交信息语义化：`feat` / `fix` / `docs` / `test` / `chore`。

## 阶段 5 · 提交与演示

1. 提交前本地自测：`npm test` 全绿。
2. 演示前：`npm run db:push && npm run seed`，再 `npm run dev` + `npm run demo`。

## 附录 A · 统一错误码规范

| 状态码 | 含义 | 触发场景 |
| --- | --- | --- |
| 400 | 请求参数错误 | 缺必填项 / 参数格式不对 |
| 401 | 未登录或登录过期 | 缺 token / token 无效 |
| 403 | 无权限 | 非管理员访问管理接口 |
| 404 | 资源不存在 | 查询的 id 不存在 |
| 500 | 服务端错误 | 未捕获异常 |

## 附录 B · 目录结构与职责

```
apps/server/
  prisma/schema.prisma        # 数据模型（阶段1）
  src/routes/*.ts             # 后台接口（阶段2）
  src/services/*.ts           # 业务逻辑（鉴权 / AI 诊断等）
  test/*.test.ts              # 接口测试（阶段2，必须随接口同步新增）
apps/dashboard/               # 前端看板（阶段3）
docs/API文档.md               # 接口文档（阶段2，随接口同步更新）
docs/开发流程规范（蓝皮书）.md # 本文件
```

## 附录 C · 如何运行接口测试

```bash
cd apps/server
npm install
npm test          # 等价于 node --test 运行 test/ 下全部 *.test.ts
```

- 测试使用**独立库** `prisma/test.db`，不会污染开发数据。
- `test/setup.ts` 会在每次运行时自动建表并清空，保证用例幂等。
- 测试框架为 Node 内置 `node:test` + Fastify `app.inject()`，无需真实端口。
