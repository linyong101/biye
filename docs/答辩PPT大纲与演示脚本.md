## 二、现场演示脚本（5–8 分钟）

### 环境与准备（答辩前 10 分钟完成）

```bash
# 方式一：本地开发（推荐，启动快）
npm install
npm run db:push
npm run build:sdk
npm run dev          # 采集服务 :3001 + 看板 :5173（另开终端）
npm run demo         # 异常制造机 :5174

# 方式二：Docker 一键部署（导师可远程访问，见部署手册）
docker compose up -d
# 看板：http://<宿主机IP>:8080   采集服务：:3001
```

默认账号：`admin / admin123`（首次登录请改密码）。

### 演示步骤（对着评委边点边讲）

1. **登录看板**（:5173 或 :8080）→ 进入「概览」页，说明核心指标卡与异常趋势图。
2. **制造异常**：切到 Demo 站点（:5174），点「触发 JS 错误」「触发未捕获 Promise」。
3. **看板实时响应**：回到概览，指出错误计数上升、趋势图出现尖峰——体现「秒级上报」。
4. **问题详情 + Source Map 还原**：进入「问题」列表 → 点开刚产生的 issue → 展示**还原后的源码位置**（如 `Order.tsx:42`），说明压缩堆栈如何被还原。
5. **AI 根因诊断**：点「开始诊断」→ 展示根因判断 + 修复建议 + 置信度（可强调「无 Key 时自动降级规则库，功能不中断」）。
6. **会话回放**（亮点）：进入「会话回放」→ 选一个「含错误」的会话 → 点「播放」→ 时间轴逐帧展示用户出错前的点击/路由路径与界面状态——体现「复现问题更直观」。
7. **告警推送**：进入「设置 → 告警规则」→ 添加一条「出现新问题」规则，Webhook 填自己的企微/钉钉机器人 → 再触发一次错误 → 手机/群聊**实时收到告警卡片**（含详情链接）。
8. **性能视角**（如有时间）：触发慢请求，切到「性能」页，说明 P75 分位与 Web Vitals。

### 演示话术要点
- 始终围绕「一行接入、私有化、中文 IM 告警、AI 双模式」四个差异点。
- 遇网络/加载问题或看板为空：答辩前务必先跑一次 `npm run seed`。它现在会一次性预置「近 7 天错误/性能数据 + 3 个会话回放剧本（购物车 500 报错 / 白屏 / 正常浏览）+ 三类告警规则（new_issue / error_spike / perf_degrade）」，确保「概览 / 会话回放 / 告警配置」三页都有内容可讲。

## 三、功能亮点（一句话讲给评委）

1. **一行接入、体量极轻**：`init({ appId, endpoint })` 即可；SDK gzip **< 10KB**，插件化按需引入，不侵入业务。
2. **错误指纹聚合**：把成千上万条重复上报压缩成几十个「问题（issue）」，自动统计发生次数与影响用户数。
3. **Source Map 还原 + AI 双模式诊断**：压缩堆栈还原到源码行列；大模型给出根因与修复建议，外部服务不可用时自动降级规则库，**功能零中断**。
4. **会话回放**：轻量 DOM 快照录屏，时间轴 + 逐帧回放，直观复现用户出错前的操作路径。
5. **三类告警推送企业 IM**：新问题 / 错误量突增 / 性能劣化，推送到企业微信、钉钉、飞书机器人。
6. **真正可私有化**：Docker Compose 一键部署（PostgreSQL + Redis），数据不出公司内网；鉴权零依赖（基于 Node 内置 `crypto`）。

## 四、评委高频提问与应答预案

**Q1：和 Sentry / 阿里云 ARMS 比，你的优势是什么？**
A：Sentry 自托管重、ARMS 仅 SaaS。本系统主打「轻量私有化 + 中文 IM 告警 + 零依赖鉴权 + 完全透明的实现原理」，适合作为毕设完整讲清每一环；体积 < 10KB 也优于两者。

**Q2：上报量很大时系统扛得住吗？**
A：三层设计——SDK 端批量+定时上报与采样；服务端「指纹聚合」把同类错误合并、批次结束统一刷新计数（避免 N 次写库）；生产可切换 PostgreSQL + Redis 限流，服务无状态可水平扩展。

**Q3：AI 诊断准不准？依赖外部大模型会不会不可用？**
A：诊断走「大模型 + 内置规则库」双模式：配了 Key 用真实模型，没配或调用失败自动回退规则库并给出基于错误类型的诊断；结果缓存在 issue 上，避免重复消耗。

**Q4：SDK 对宿主页面性能有影响吗？**
A：性能采集全部基于 `PerformanceObserver` 被动订阅，**零轮询、不阻塞主线程**；SDK 体积小、上报走 `sendBeacon` 不抢主流程。

**Q5：会话回放会不会泄露用户隐私？**
A：回放只采集 DOM 节点的**矩形坐标与文本摘要**，不过载完整 DOM/截图；SDK 默认脱敏 `password / token / 身份证` 等字段，可自定义脱敏规则。

**Q6：为什么不用现成监控平台，要自己造？**
A：本课题重点在「设计 + 实现 + 验证」完整闭环，涵盖采集、聚合、还原、诊断、权限、部署全链路；自研才能把每一处算法（指纹、白屏、上报）与创新点讲透，也满足数据私有化合规诉求。
